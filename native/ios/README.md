# Narsil Pro (The Explorer's Guild) — iOS StoreKit setup

`NarsilStoreKit.swift` is the native half of the subscription. It is kept here
rather than in `ios/` because `ios/` is generated by `npx cap add ios` (macOS
only) and is gitignored on this project — anything placed inside it is lost the
next time the platform is regenerated.

## 0. Photo library usage description (required)

Saving an extract via the share sheet → **Save Image** writes to Photos. iOS
aborts the process if `Info.plist` is missing
`NSPhotoLibraryAddUsageDescription` (TCC privacy crash).

`npm run cap:sync` runs `scripts/patch-ios-info-plist.mjs`, which merges that
key into `ios/App/App/Info.plist`. If you only re-copied Swift files, run:

```bash
npm run patch:ios-plist
```

Then rebuild in Xcode (`⌘R`).

## 1. Add the plugin to the Xcode project

After `npx cap add ios`:

```bash
cp native/ios/NarsilStoreKit.swift ios/App/App/
cp native/ios/MainViewController.swift ios/App/App/
npm run cap:sync
npm run cap:ios
```

In Xcode, confirm both files appear under the **App** target (Build Phases →
Compile Sources). No `.m` bridging file is needed.

Then wire up the registration — Capacitor only auto-registers plugins that
arrive as packages; an app-local plugin must be registered in code or every
call to it rejects with `UNIMPLEMENTED`:

1. `MainViewController.swift` subclasses `CAPBridgeViewController` and calls
   `bridge?.registerPluginInstance(NarsilStoreKit())` — already written, just
   ensure it's compiled into the target.
2. Open `App/Base.lproj/Main.storyboard`, select the view controller, open the
   **Identity Inspector** (⌥⌘3), and set **Custom Class** to
   `MainViewController` (Module: `App`, "Inherit Module From Target" is fine).
   The template ships with `CAPBridgeViewController` there; ours must replace
   it or `capacitorDidLoad()` never runs.

Re-copy the file after any `npx cap add ios` / `npx cap sync` that regenerates
the platform.

## 2. Capabilities and deployment target

- **In-App Purchase** capability on the `App` target.
- **Minimum deployment target iOS 15.0** — StoreKit 2 (`Product`,
  `Transaction.updates`, `VerificationResult.jwsRepresentation`) does not exist
  below that. Set it in the target's General tab and in `Podfile`
  (`platform :ios, '15.0'`).

## 3. App Store Connect

Create **one subscription group** — `Narsil Pro` — containing two products:

| Product ID | Duration | Price |
|---|---|---|
| `com.narsil.museum.pro.monthly` | 1 month | $4.99 |
| `com.narsil.museum.pro.annual` | 1 year | $39.99 |

Add a **7-day free trial** introductory offer to both. Keeping them in the same
group is what lets a user switch between monthly and annual with Apple
handling proration.

The ids must match `PRO_MONTHLY` / `PRO_ANNUAL` in
[`src/lib/storekit.ts`](../../src/lib/storekit.ts) and the backend's
`APPLE_PRODUCT_IDS`.

## 4. Server notifications

App Store Connect → your app → **App Store Server Notifications**, V2:

```
Production URL: https://<backend>/api/apple/notifications
Sandbox URL:    https://<backend>/api/apple/notifications
```

Set **both**. Without the sandbox URL, TestFlight renewals and cancellations
never reach the backend and entitlements never expire in testing.

## 5. Backend credentials

App Store Connect → Users and Access → **Integrations → App Store Connect API**
→ generate a key with the *In-App Purchase* role. Then in the backend `.env`:

```dotenv
APPLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n…\n-----END PRIVATE KEY-----"
APPLE_KEY_ID=ABC123XYZ
APPLE_ISSUER_ID=00000000-0000-0000-0000-000000000000
APPLE_BUNDLE_ID=com.narsil.museum
APPLE_APP_APPLE_ID=1234567890
APPLE_ENVIRONMENT=Sandbox          # Production for the live app
APPLE_ROOT_CA_DIR=certs/apple
```

Download Apple's root certificates from
<https://www.apple.com/certificateauthority/> (**Apple Root CA - G3** is the one
that signs App Store data) into `certs/apple/`. Signature verification cannot
run without them, and the backend refuses to guess — while any credential is
missing the whole subscription tier no-ops and nobody is a subscriber.

## 6. Testing

### In the Simulator (no App Store Connect needed)

`Product.products(for:)` returns an **empty list** in the Simulator unless a
StoreKit Configuration file is attached to the scheme — the paywall then shows
"Plans are unavailable right now". `NarsilPro.storekit` in this folder defines
both products with the 7-day trial:

1. Xcode → add `native/ios/NarsilPro.storekit` to the project (reference is
   fine, no target membership needed).
2. Product → Scheme → **Edit Scheme… → Run → Options → StoreKit
   Configuration** → select `NarsilPro.storekit`.
3. Run. Purchases are simulated locally — no sandbox account, no real charge.

Note: locally simulated transactions are signed with Xcode's test certificate,
**not** Apple's root CA, so the backend's JWS verification will reject them.
The `.storekit` file is for exercising the paywall UI and purchase sheet; the
full purchase → entitlement path needs sandbox (below).

If the paywall instead says "Subscriptions aren't available in this build",
`NarsilStoreKit.swift` isn't compiled into the target — redo step 1 of this
README. Check Safari Web Inspector's console for `[ProPaywall]` errors to tell
the two apart.

### Sandbox (device / TestFlight)

Products load from App Store Connect only once they exist there, are at least
"Ready to Submit", and the **Paid Applications agreement** is signed — until
then the paywall is empty even on a real device.

Sandbox testers: App Store Connect → Users and Access → **Sandbox Testers**.
Sign out of the App Store on the device first; the sandbox prompt appears at
purchase time.

Sandbox subscriptions renew on an accelerated clock — a 1-month subscription
renews every 5 minutes, and auto-renews 6 times before expiring. That is what
makes it practical to test `DID_RENEW`, `EXPIRED` and the grace-period path in
an afternoon.

Worth testing explicitly, because each is a different code path:

- purchase → entitlement appears and the Guild perks unlock: endless practice,
  every age / empire trial, Master File downloads, uploading in Create
- cancel in Settings → `EXPIRED` arrives and `?res=high` returns 402
- refund (App Store Connect can issue one in sandbox) → `REFUND` → entitlement
  revoked immediately
- delete the app, reinstall, sign in, **Restore Purchases** → entitlement returns

## Push notifications

The app asks for notification permission after someone buys a print or finishes
the daily quiz, and from Profile → Notifications. The backend sends the notifications
straight to Apple (`narsil-museum-backend/src/services/push.ts`).

1. Copy the AppDelegate hook into the project:

   ```bash
   cp native/ios/PushNotifications.swift ios/App/App/
   npm run cap:sync
   ```

   Confirm it is listed under the **App** target (Build Phases → Compile Sources).
2. In Xcode → target **App** → **Signing & Capabilities**, add **Push Notifications**.
3. Create an APNs key: Apple Developer → **Certificates, Identifiers & Profiles → Keys** →
   **+**, tick **Apple Push Notifications service (APNs)**, then download the `.p8` file
   (Apple only lets you download it once). Put these in the backend `.env` on EC2:

   ```dotenv
   APNS_KEY="-----BEGIN PRIVATE KEY-----\n…\n-----END PRIVATE KEY-----"
   APNS_KEY_ID=ABC123DEFG        # shown next to the key
   APPLE_TEAM_ID=XXXXXXXXXX      # Apple Developer → Membership
   # APNS_ENVIRONMENT=sandbox    # only for builds run straight from Xcode
   ```

   Then restart the server with `pm2 restart narsil-backend --update-env`.
4. Run `supabase/push-notifications.sql` in Supabase.

## Shared links open the app (Universal Links)

Links shared from the app look like `https://d2lvgalchu2nps.cloudfront.net/share/<id>`.
To make them open the installed app instead of Safari:

1. Set `APPLE_TEAM_ID` on the backend (same value as above). The backend then serves
   `/.well-known/apple-app-site-association`.
2. In Xcode → **Signing & Capabilities**, add **Associated Domains** with the entry
   `applinks:d2lvgalchu2nps.cloudfront.net`.

Without this, shared links still work: they show a picture preview and open the web
app.
